9月29日に配信が始まったWindows 11の2026年版、バージョン26H2を入れてからタスクマネージャーを開くと、起動した直後のメモリ使用量が以前より少なく表示されることに気づいた人は多いと思う。新機能の一覧にはほとんど書かれていないのに、16GB以上のメモリを積んだ機種では、起動直後の使用量が1.5〜2GBほど下がるという変化が出ている。

DAWで曲を作っている立場からすると、空きメモリが2GB増えるのはうれしい話に聞こえる。ただ、音切れやプチノイズが減るのか、読み込めるサンプル音源が増えるのかというと、話は少し分けて考える必要がある。この記事では、26H2でメモリが減った仕組みと、8GBの機種で変化が小さい理由を整理したうえで、制作PCで効くことと効かないこと、そして更新の前に確かめておきたい音まわりの不具合をまとめる。

## 26H2は小さな更新で、中身の多くはすでに届いていた

最初に押さえておきたいのは、26H2がOSを丸ごと入れ替える大型の更新ではないという点だ。24H2・25H2と同じ土台のうえに、毎月の更新ですでに配られていた機能を「有効にする」ための小さなパッケージ（イネーブルメントパッケージ）として届く。ダウンロードは数百KB程度で、再起動は1回だけで済み、ビルド番号は26300系になる。

つまり、メモリの使い方を改善するコードの多くは、24H2や25H2を使っている間にも少しずつ届いていて、26H2でまとめてスイッチが入ったと考えると分かりやすい。Microsoftは7月の時点で、Windows 11のメモリ消費の多さを認め、8GBの機種でも快適に動くように年内に手を入れると表明していた。26H2は、その取り組みが目に見える形になった最初の区切りだと受け止めている。

減った理由として挙げられているのは、大きく分けて次のようなものだ。メモリ管理の見直しで、使っていない機能のためにメモリを先に確保しておくのをやめ、実際にその機能を使うときに確保するようになったこと。メモリ圧縮とスタンバイリストの扱いが改善されたこと。Windowsの画面部品を作るWinUIで、使っているうちにメモリが膨らんでいく不具合がまとめて直されたこと。エクスプローラーのメモリ使用量が減ったこと。どれか一つが劇的に効いたというより、小さな改善の積み重ねで起動直後の数字が下がった、という性格の変化に見える。

## 減るのは16GB以上の機種、8GBでほとんど変わらない理由

<figcaption>ノートPCに載ったSO-DIMMのメモリ。容量が少ない機種ほど、Windowsはもともと積極的にメモリを圧縮している<span class="credit">Photo: Diego Torres Silvestre / <a href="https://commons.wikimedia.org/wiki/File:Crucial_CT4G4SFS8213_on_laptop_motherboard_20171218.jpg" target="_blank" rel="noopener">CC BY 2.0</a></span></figcaption>
</figure>

報告されている数字を並べると、32GBの機種で起動直後に9GB台だった使用量が7GB台半ばに、64GBの機種で11GB台が9GB台にと、16GB以上の機種ではおおむね1.5〜2GBほど下がっている。常駐ソフトが多かったノートPCでは、3GB近く下がった例もある。

一方で、8GBの機種では、更新の前後で使用率がほとんど変わらないという結果が目立つ。逆に感じるかもしれないが、これには理由がある。メモリに余裕のあるPCでは、Windowsは「どうせ空いているから」と、すぐには使わないデータもメモリに置いたままにしておく。この余分な部分が、今回の改善で削れた分だ。

ところが8GBの機種では、Windowsは以前から、メモリが足りなくならないように常に圧縮したり、使っていないページを追い出したりしている。もともと余分な部分がほとんど残っていないので、新しい改善が入っても削れる場所がない。8GBの機種で「26H2を入れたのに軽くならない」と感じても、それは更新が失敗しているわけではなく、すでに限界まで詰めた状態で動いていた、ということになる。

この点は、制作PCの買い替えやメモリ増設を考えている人にとって大事だと思う。26H2で空きが増えるのは、もともと余裕のある機種の話であって、8GBの機種がこの更新だけで16GBの機種に近づくわけではない。

## DAWで体感できること、できないこと

では、16GB以上の制作PCで2GB前後の空きが増えたとき、DAWの作業で何が変わるのか。結論から言うと、効くのは「メモリに読み込む量」に関わる部分で、「音が途切れるかどうか」にはほとんど関係しない。

効きそうなのは、サンプル音源を多く使う場面だ。ピアノやドラム、オーケストラ系の音源は、音の立ち上がり部分をあらかじめメモリに置いておき、残りをストレージから少しずつ読み出す仕組みになっている。この先読みの部分は、音源を立ち上げるたびに積み上がっていく。16GBの機種で、ブラウザや配信ソフトと同時にDAWを開き、音源を何本も立ち上げているような使い方なら、2GBの余裕が生まれることで、メモリ不足からストレージへの書き出しが始まるまでの距離が少し伸びる。プロジェクトを開くときの待ち時間が短くなったり、重いプロジェクトの切り替えが少し楽になったりするのは、このあたりの効果だと思う。

一方で、録音や再生中のプチノイズ・音切れは、ほとんどの場合メモリの量ではなく、決められた時間内に音の計算が終わるかどうかで決まる。オーディオインターフェースのバッファーサイズ、CPUの処理能力、そして特定のドライバーが処理を長く止めてしまう「DPCレイテンシ」と呼ばれる遅延が主な原因になる。26H2でこの部分が改善されたという話は見当たらず、バッファーを小さくしたときの安定性が上がることは期待しないほうがいい。

もう一つ、26H2ではスタートメニューやアプリの起動時に、ごく短い時間だけCPUのクロックを上げて素早く処理を終わらせる「低遅延プロファイル」の効果も語られている。ただ、これは26H2で初めて入った仕組みではなく、DAWの再生中の負荷とは別の話だ。アプリの立ち上がりが軽く感じられることはあっても、トラック数を増やせるようになるわけではない。

音切れ対策として効くのは、26H2の前から変わらない、いつもの見直しだ。メモリが減ったことで安心せず、こちらを一度確かめておくほうが、制作中の安定性にはずっと効くと思う。

まず電源プランを「高パフォーマンス」にする。既定の「バランス」では、負荷が軽いときにCPUのクロックが下がり、急に負荷がかかったときに上がりきるまでの間で処理が間に合わず、音が途切れることがある。詳細設定で「最小のプロセッサの状態」を100%にしておくと、さらに確実になる。あわせて、録音中に画面が消えたりスリープに入ったりしないよう、スリープとディスプレイの電源オフも「なし」にしておくと安心だ。

次に、電源プランの詳細設定にある「USBのセレクティブサスペンド」を無効にする。これが有効のままだと、Windowsが省電力のためにUSB機器を休ませようとして、オーディオインターフェースやMIDIキーボードの接続が途切れる原因になる。インターフェースはUSBハブを通さず、PC本体のポートに短いケーブルで直接つなぐのが基本だ。

ドライバーは、Windows Updateが入れる汎用のものではなく、インターフェースのメーカーが配っているASIOドライバーを使う。グラフィックボードについても、ゲーム向けの付属ソフトまで入れると、常駐して処理を食うことがあるので、ドライバー本体だけにしておくのがいい。

ほかに見直しておきたいのは、ゲームモードとXbox Game Bar、Windowsの音響効果（オーディオ拡張）、録音データを置くドライブでの検索インデックス作成、そしてOneDriveなどのクラウド同期だ。とくにクラウド同期は、録音したばかりの大きなファイルを作業中にアップロードし始めることがあるので、制作中は一時停止しておくと落ち着く。

それでも音切れが続く場合は、LatencyMonのような計測ソフトで、どのドライバーが処理を長く止めているかを調べるのが近道になる。無線LANやBluetooth、グラフィックのドライバーが原因になっていることが多く、メモリをいくら増やしても、ここが原因なら音切れは消えない。

## 更新の前に確かめておきたい、音まわりの既知の問題

<figcaption>ドライバーなしで使えるUSBオーディオ機器。汎用のクラスドライバーで動く機器ほど、Windows側の変更の影響を受けやすい<span class="credit">Photo: Itu / <a href="https://commons.wikimedia.org/wiki/File:USB-Audio-Interfaces.jpg" target="_blank" rel="noopener">CC BY-SA 3.0</a></span></figcaption>

DAWを使う人にとって、26H2で一番気にしておきたいのはメモリよりもこちらだと思う。Microsoftの既知の問題の一覧には、USB Audio Class 1.0に対応した機器が起動しなくなる不具合が載っている。デバイスマネージャーで「このデバイスを開始できません（コード10）」と表示されたり、サウンドの設定画面が反応しなくなったり、音量がゼロのまま動かなくなったりする症状だ。

この不具合は26H2だけでなく、24H2や25H2にも同じ時期の月例更新から及んでいて、「26H2を入れなければ避けられる」という種類の問題ではない。Microsoftは影響を抑える対応を進めているものの、完全な修正はこれからの更新に持ち越されていて、回避策としては多チャンネルの設定をステレオに落とす方法が案内されている程度だ。

USB Audio Class 1.0は、専用ドライバーなしで挿すだけで使える、古めの小型インターフェースやUSBマイク、ヘッドホンアンプなどで使われている規格だ。メーカーのASIOドライバーで動く現行のインターフェースなら影響を受けにくいはずだが、サブの機材として小型のUSBオーディオ機器を使っている人は、更新後にまず音が出るかを確かめておきたい。

もう一つ、WindowsのAC-3（ドルビーデジタル）デコーダーを使うアプリが、起動しない・再生中に落ちるという問題も確認されている。DAWでの制作にはあまり関係しないが、動画の音声を確認するソフトや、古いゲームで症状が出ることがある。

締め切りの近い作業を抱えているなら、更新は作業の区切りがついてからにして、更新後はインターフェース・MIDI機器・よく使う音源を一通り鳴らしてから本番の作業に戻るのが安全だと思う。

## まとめ

| 項目 | 26H2で変わるか | 制作PCでの受け止め方 |
|---|---|---|
| 起動直後のメモリ使用量 | 16GB以上で1.5〜2GBほど減る | サンプル音源を多く立ち上げる作業に少し余裕が出る |
| 8GBの機種 | ほぼ変わらない | 増設や買い替えの判断材料にはならない |
| 音切れ・プチノイズ | 変わらない | 電源プラン、USBの省電力、ドライバーの見直しが先 |
| アプリの起動 | 少し軽く感じることがある | トラック数や同時発音数が増えるわけではない |
| USBオーディオ機器 | Class 1.0機器に既知の不具合あり | 更新後にすべての機器で音が出るか確かめる |

26H2のメモリ削減は、16GB以上のPCを使っている人にとっては、ありがたいおまけのような変化だと思う。ただ、DAWの安定性を決めているのは、メモリの空きよりも、CPUの処理が時間内に終わるかどうかと、ドライバーのふるまいのほうだ。更新をきっかけに電源プランとUSBまわりの設定を一度見直し、使っている機器が問題なく動くかを確かめておけば、26H2の恩恵を気持ちよく受け取れるはずだ。
