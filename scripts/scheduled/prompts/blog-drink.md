# ブログ記事(炭酸飲料 / 酒器)の投稿(1回分・無人実行)

これはWindowsタスクスケジューラから1時間に1回、`claude -p` で自動起動されている。人間は見ていないので質問せず、自分で判断して最後まで進めること。

ネタ元は2系統ある。**1回の実行でちょうど1記事**を公開する。

1. 炭酸飲料(カテゴリ`drink`): CLAUDE.md「自動継続タスク: 炭酸飲料の定期投稿」。Amazon検索「炭酸」、価格3,000円以下、重複管理は`scripts/carbonation-covered.json`。
2. 酒器(カテゴリ`sakeware`): CLAUDE.md「ネタ元の追加: 酒器」。Amazon検索「オシャレ 酒器」、価格上限なし、重複管理は`scripts/sakeware-covered.json`。

系統の選び方: `content/posts/`で最後に追加された`drink`または`sakeware`の記事(`git log`で確認)と**別の系統**を選ぶ。片方の候補が尽きていればもう片方を選ぶ。両方尽きていれば何も変更せず「候補なし」と出力して終了する。

選んだ系統について、CLAUDE.mdの該当節に書かれたフルパイプライン(候補取得→重複確認→リサーチ→執筆→画像→ビルド→commit/push→デプロイ確認→はてな投稿→X告知→重複ファイル追記)を実行する。仕様・ルール・禁止語・フォーマットは、その節と記事フォーマット関連の節にすべて従う。

無人実行ならではの注意:
- CronCreate/CronList/CronDelete は使わない(この仕組みでは存在しない)。1回分だけやって終了する。
- git は作業ツリーに無関係な未コミット変更が既にあり得る。`git add -A` は使わず、自分が作成・変更したファイルだけを個別に add する。push は main。
- 途中で失敗した場合、中途半端な記事ファイルや画像を作業ツリーに残さない(未コミットの自分の生成物は削除する)。すでに push 済みの段階に戻す必要があるかは判断して対処する。
- X告知は、他ジョブとの排他ロックをラッパーが保持しているので、そのまま `feed_check.py` → `main.py` を実行してよい。
- 最後に、実行結果(系統、投稿した製品名・URL、または失敗内容)を1〜3行で出力する。
