# ブログ記事(テーマ記事)の投稿(1回分・無人実行)

これはWindowsタスクスケジューラから1時間に1回、`claude -p` で自動起動されている。人間は見ていないので質問せず、自分で判断して最後まで進めること。

**1回の実行でちょうど1記事**を公開する。

## ネタ元

`C:\Users\norio\x_bot\themes.txt` に1行1テーマで並んだリスト(現在14件)。ここが唯一のネタ元であり、**Amazon検索は使わない**。

1. 上記ファイルを読み込む。空行・コメント行(`#`始まり)を無視し、残りを1行ずつテーマとして扱う。
2. `scripts/theme-covered.json` の `covered` 配列にあるテーマは選出対象外(既出のためスキップ)。
3. `covered` にないテーマを**1つだけ**選ぶ。選ぶ基準は「前回公開した記事とテーマが重ならないこと」。順番は問わない。
4. 1件も残っていなければ、何も変更せず「候補なし」と出力して終了する。

**選出したテーマは必ず永続ファイルに記録する。** 公開後に `scripts/theme-covered.json` の `covered` へ `theme` / `slug` / `date` / `note` を追記して commit する。これが重複防止の唯一の永続的な状態なので、**更新を絶対に忘れないこと**。

## カテゴリ

- 音楽・ジャズ（アルバム・フェスティバル・演奏者） → カテゴリID `music`（既存カテゴリ）
- ファッション（ジャケット・靴・帽子の流行） → カテゴリID `fashion`（既存カテゴリ）

記事のfront-matterにあるカテゴリは上記から必ず**1つだけ**使う。正式カテゴリは `hugo.toml` の `[menu]` に登録済みなので、新規追加は不要。

## 記事フォーマット

- 型その2（単発製品深掘り）の**タイトル規則と文体**に従う。タイトルは「{テーマ}を隅から隅まで味わい尽くす — {詩的サブタイトル}」形式
- リサーチは最低10サイト以上（英語圏の音楽メディアと一般メディアの両方）。一次情報（公式・アーティスト公式サイト・報道）を優先
- 文体・引用ルール・禁止語は既存の他記事と完全に共通。CLAUDE.md の記事フォーマット関連節に従う
- アフィリエイトバナーは**製品記事ではないため不要**（商品ページがない）。購入導線枠を入れない
- 評価軸・レーダーチャートは使わない（比較対象がない）

## 画像

- 参照元のページの画像を1枚以上取得する。公式・ニュース記事・写真作品の画像を使い、権利表示（撮影者・ライセンス）を `<span class="credit">` に記載する
- 参照元に画像が無い場合のみ Web 検索で関連画像を確保する
- 配置は `photo photo--left` / `photo photo--right` を使い、文字が画像へ回り込む形にする。1行10文字以下にしない可読性を保つ（画像幅220px以下、向かい合う2枚の間は180px以上）

## 毎回のフルパイプライン

(1) `themes.txt` + `theme-covered.json` でテーマを1つ選ぶ → (2) Agent(general-purpose)で最低10サイト以上リサーチ → (3) 記事執筆(`content/posts/`) → (4) 画像取得(`static/images/`) → (5) `hugo --minify`でビルド確認 → (6) commit & push → (7) GitHub Actionsデプロイ確認 → (8) `scripts/extract-post-html.sh`+`scripts/post-to-hatena.sh`ではてなブログに新規投稿。**`post-to-hatena.sh`を使う。`update-hatena-post.sh`ではない**（新規記事なので）。発行されたEntry IDをCLAUDE.mdの表に追記 → (9) `scripts/theme-covered.json`にテーマを追記してcommit。

## 無人実行ならではの注意

- CronCreate/CronList/CronDelete は使わない(この仕組みでは存在しない)。1回分だけやって終了する。
- git は作業ツリーに無関係な未コミット変更が既にあり得る。`git add -A` は使わず、自分が作成・変更したファイルだけを個別に add する。push は main。
- 途中で失敗した場合、中途半端な記事ファイルや画像を作業ツリーに残さない(未コミットの自分の生成物は削除する)。すでに push 済みの段階に戻す必要があるかは判断して対処する。
- 最後に、実行結果(選んだテーマ・記事URL、または失敗内容)を1〜3行で出力する。
